Vuestro entorno

Peticiones listas para pegar en vuestro Claude Code, en vuestro equipo. En cada paso, Claude os pregunta lo que necesita de vuestro entorno y os guía; vosotros decidís. Debajo de cada petición, por si queréis saber más, las opciones que ya están averiguadas.

  1. 1

    El esfuerzo: déjalo en medio

    Diapositiva 7 ↗

    Cuánto piensa Claude antes de actuar. medium es el valor por defecto en los modelos actuales y sirve para casi todo. Para un turno difícil, no cambies el ajuste: escribe ultrathink en la petición.

    En Claude Code

    NivelPara qué
    lowPreguntas rápidas, renombrar
    mediumLo normal
    high · xhighCuando importa comprobar: un error difícil
    maxProblemas muy difíciles; tiende a pensar de más
  2. 2

    Que no pare hasta cumplirlo: /goal

    Diapositiva 9 ↗

    Después de cada turno, un modelo pequeño lee la conversación y decide si se cumple. No ejecuta nada: la condición tiene que verse en la conversación (una nota, la salida de un comando). Y ponle siempre un tope.

    Mejorar con usuarios simulados
    /goal Despacha 3 subagentes que actúen como usuarios de perfiles distintos:
<perfil 1>, <perfil 2> y <perfil 3>. Cada uno revisa la aplicación como si la
usara, la puntúa de 1 a 10 con los mismos criterios (claridad, rapidez para su
tarea, errores) y propone los 3 cambios que más la mejorarían. Escribe la nota
media inicial. Después, haz pases de mejora: aplica los cambios más repetidos,
comprueba que los tests siguen pasando y vuelve a puntuar con subagentes nuevos.
Escribe la nota de cada pase. Termina cuando la media haya subido al menos
1 punto sobre la inicial, o tras 10 pases.

    Las notas las pone el propio Claude: sirven para orientar, no como medida exacta. Por eso los mismos criterios en cada pase, subagentes nuevos cada vez (que no recuerden la nota anterior) y los tests en verde. Haz un commit antes de empezar: si no te gusta el resultado, vuelves atrás.

    Más corto: que compile o que pase
    /goal <el cambio> está hecho, <compila / los tests pasan> y me enseñas la
salida. O para tras 10 turnos.

    /goal sola enseña el estado; /goal clear lo quita.

    Diapositiva 16 ↗

    Claude trabaja con ficheros y con la terminal. Si el código está dentro del servidor, primero hay que acercárselo. Que te guíe él:

    Pídeselo a Claude · en una carpeta nueva y vacía

no en ficheros. Quiero que puedas leerlo. Guíame paso a paso, una cosa cada vez,
para tenerlo en una carpeta de este equipo, con la extensión de VS Code que ya
uso. Antes de nada, pregúntame lo que necesites saber de mi entorno. Asegúrate
conmigo de que nada se sube al servidor sin que yo quiera. No cambies nada en
el servidor.

    ¿Te atascas? Pégale a Claude lo que te sale y pregúntale qué significa y qué haces.

    Para saber más: las opciones que hay y cómo se exporta

    Claude trabaja con ficheros y con la terminal. El código de IRIS está dentro de la base de datos, así que hay que acercárselo. Estas son las opciones:

    OpciónPara quéQué hace falta
    1. Exportar con VS Code
    Para empezar    		Leer y explorarLa extensión InterSystems ObjectScript, que ya usáis
    2. API REST de IRIS (Atelier)
    Para trabajar    		Leer, guardar y compilar desde la terminalUsuario con %Development y la aplicación /api/atelier habilitada (si VS Code os funciona, lo está)
    3. Exportar desde el terminal de IRISLeer, si no tienes VS Code$SYSTEM.OBJ.ExportUDL, una clase cada vez
    4. Un servidor MCPLo mismo que la 2, como herramientas de ClaudeLos que hay son de la comunidad, sin soporte de InterSystems. Solo si la 2 se queda corta
    5. Que Claude maneje la pantalla—Existe, pero es lento, frágil y difícil de controlar. No lo recomendamos para esto

    Exportar con VS Code (opción 1):

    1. Crea una carpeta nueva y ábrela en VS Code, con vuestra conexión de siempre.
    2. Ctrl+Shift+P → ObjectScript: Export Code from Server → elige las clases de tu zona.
    3. Quedan en src/, una carpeta por paquete (src/Paquete/Clase.cls).
    4. En esa carpeta, en la terminal: claude

    Cuidado: en una carpeta conectada, al guardar un fichero en VS Code la extensión lo sube al servidor y lo compila (objectscript.compileOnSave, activado por defecto). Para explorar, no edites: usa plan mode.

  2. I

    IRIS: que Claude te guíe para compilar

    Diapositiva 23 ↗
    Pídeselo a Claude
    Quiero que puedas compilar tú las clases de IRIS y leer los errores, desde la
terminal y sin instalar nada: IRIS tiene una API REST (Atelier), la misma que usa
VS Code. Guíame paso a paso y pregúntame lo que necesites de mi entorno, una cosa
cada vez. Siempre en el entorno de desarrollo, nunca en producción. Las
credenciales las pondré yo a mano en variables de entorno: dime cómo, pero no me
pidas la contraseña ni la escribas en ningún fichero. Empieza por comprobar la
conexión sin cambiar nada. Antes de compilar, pregúntame si el namespace es solo
de desarrollo o lo compartimos con otros (o es producción): si no es solo de
desarrollo, no compiles; quédate en leer y apunta en el CLAUDE.md que falta
decidir dónde se compila. Si lo es, compila una clase que yo elija y enséñame la
respuesta, y apunta en el CLAUDE.md cómo se compila.

    Los pasos siguientes son lo mismo, más detallado: úsalos si Claude se pierde o si quieres saber qué está haciendo.

  3. I

    IRIS, más detalle: las credenciales, a mano

    Diapositiva 24 ↗
    Esto, a mano y fuera de ClaudeEs un secreto: no se lo des a Claude ni lo escribas en un fichero del proyecto. Queda en tu usuario de Windows. Cierra la terminal y ábrela de nuevo antes de arrancar claude.
    PowerShell (cambia lo que va entre < >)
    [Environment]::SetEnvironmentVariable("IRIS_URL", "https://<servidor>:<puerto>/api/atelier/v1/<NAMESPACE_DESARROLLO>", "User")
[Environment]::SetEnvironmentVariable("IRIS_USER", "<tu usuario>", "User")
[Environment]::SetEnvironmentVariable("IRIS_PASS", "<tu contraseña>", "User")

    La dirección es la misma que usa VS Code (servidor, puerto y, si lo hay, el prefijo), más /api/atelier/v1/ y el namespace.

  4. I

    IRIS, más detalle: probar la conexión y compilar

    Diapositiva 23 ↗
    Pídeselo a Claude
    Usa la API REST de IRIS (Atelier) con Invoke-RestMethod y autenticación básica.
La dirección del namespace de desarrollo está en la variable de entorno IRIS_URL,
y el usuario y la contraseña en IRIS_USER e IRIS_PASS. Léelas del entorno y no
enseñes nunca la contraseña.
1. GET a la raíz de la API (IRIS_URL sin "/v1/<namespace>") para ver la versión
   y los namespaces.
2. Lista las clases del paquete <Paquete>: GET {IRIS_URL}/docnames/CLS
3. Compila <Paquete.Clase>.cls: POST {IRIS_URL}/action/compile con el cuerpo
   ["<Paquete.Clase>.cls"] en JSON, y enséñame la respuesta.
No guardes ni cambies ninguna clase. Si algo falla, dime el código de error y
qué significa.
    ErrorLo más probable
    401Usuario o contraseña, o la terminal no ha cargado las variables: ábrela de nuevo
    403Al usuario le falta el recurso %Development (rol %Developer): quien administra IRIS
    404La dirección, o la aplicación web /api/atelier deshabilitada
    409Al guardar: alguien cambió la clase en el servidor desde que la leíste. No lo fuerces: vuelve a leerla
  5. I

    IRIS: un script para el día a día

    Diapositiva 23 ↗

    Cuando la conexión funcione, que Claude se escriba su propia herramienta. Así no tiene que acordarse de la API cada vez.

    Pídeselo a Claude
    Escribe herramientas/iris.ps1 con tres órdenes, usando la API Atelier y las
variables IRIS_URL, IRIS_USER e IRIS_PASS (nunca escribas la contraseña):
- traer <Clase>: GET {IRIS_URL}/doc/<Clase>.cls y guárdala en src/ (una carpeta
  por paquete). Guarda también la marca de tiempo que devuelve.
- subir <Clase>: PUT {IRIS_URL}/doc/<Clase>.cls con el contenido del fichero.
  Envía la marca de tiempo de la última lectura para que, si alguien la ha
  cambiado en el servidor, falle con 409 en vez de pisarla. Nunca uses
  ignoreConflict.
- compilar <Clase>: POST {IRIS_URL}/action/compile y enseña los errores.
Pruébalo con traer y compilar sobre <una clase que no importe>. No uses subir
hasta que yo te lo diga. Después, explica en el CLAUDE.md cómo usarlo.

    Antes de dejar que Claude suba cambios, comprobad con quien administra IRIS que los cambios que entran por la API quedan registrados en vuestro control de cambios, igual que los de VS Code.

  6. I

    IRIS: los tests

    La API Atelier no tiene una orden para lanzar %UnitTest. Hay que decidir cómo con quien administra IRIS. Las opciones que conocemos (ninguna probada en el curso):

    • Un método de clase que llame a ##class(%UnitTest.Manager).RunTest(...), expuesto como procedimiento SQL, que Claude llame con POST {IRIS_URL}/action/query.
    • Un pequeño servicio REST propio, solo en el namespace de desarrollo, que lance los tests y devuelva el resultado.
    • Mientras tanto: Claude compila, y los tests los lanzáis vosotros como hoy y le pegáis el resultado.
    Pídeselo a Claude
    /plan En IRIS lanzamos los tests así: <cómo lo hacéis hoy>. Quiero que tú
puedas lanzarlos y leer el resultado. La API Atelier no tiene una orden para
%UnitTest. Compara estas opciones para nuestro caso, con sus riesgos:
(a) un método que llame a %UnitTest.Manager.RunTest expuesto como procedimiento
SQL y llamado con action/query; (b) un servicio REST propio en el namespace de
desarrollo. Dame enlaces a la documentación oficial. No cambies nada.
